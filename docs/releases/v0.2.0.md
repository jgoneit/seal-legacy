# Harness v0.2.0

Harness v0.2.0 is an Experimental release of the local outcome-verification
Core and Codex Plugin. It records source-bound verification Evidence v2 and
evaluates explicit completion claims without controlling how a coding Agent
implements a Task.

## Highlights

- **S0/S1/S2 Source Binding:** `verify` records the product-source identity
  immediately before checks as S0 and after checks as S1. `complete` collects
  current S2 and requires S0 = S1 = S2.
- **Fixed Task baseline:** `task create` saves the full baseline commit.
  Verification uses that baseline; the Run-level `verify --base-ref` override
  has been removed.
- **Canonical stored Run validation:** `validate_run()` is the public authority
  for stored Task/Run identity, Evidence v2 documents, Source Snapshots, and Run
  Manifest integrity. Bundle, Verdict, and completion consumers use that
  validated result.
- **Raw-byte Evidence manifest:** the Run Manifest records the exact mechanical
  file set with raw-byte sizes and SHA-256 digests.
- **Manual Verdict binding:** a user-provided Manual Verdict is validated and
  recorded against the exact Task and Run after stored Run validation.
- **Fail-closed completion:** missing, corrupt, contradictory, or unsupported
  Evidence is rejected before source, verifier, Scope, timeout, and
  required-check policy gates are evaluated.
- **Bounded Bundle sanitization:** bundle export replaces only known spellings
  of the active repository root and user home. Ordinary POSIX, Windows, UNC,
  URL-like, source-code, and log path literals remain unchanged.
- **Evidence v2 only:** Core reads source-bound verification schema version 2
  Runs only.

## Completion profiles

- **Basic mechanical-only profile:** `verifier.required` is `false`.
  Completion can succeed without a Manual Verdict when source binding, Scope,
  timeout, and required-check gates pass.
- **Reviewed profile:** `verifier.required` is `true`. Completion additionally
  requires a separately prepared `pass` Manual Verdict with zero blockers.

Harness does not select or execute a reviewer. Bundle export, Verdict
recording, and completion remain explicit operations.

## Breaking changes

- v0.2 Core does not read v0.1.x verification Runs.
- Use the CLI from the corresponding v0.1.x Git tag to read v0.1.x Evidence.
- There is no in-place Evidence migration, compatibility adapter, or automatic
  upgrade.
- `verify --base-ref` has been removed. The saved Task baseline is the only
  verification baseline.
- The Codex Skill no longer has a legacy v0.1.x behavior profile.
- `complete` returns exit 9 when the current source does not match the
  post-check source recorded by the verified Run.

Task, changed-files, checks, Run Manifest, Bundle, Verdict, Completion, and
Source Snapshot schema versions are unchanged. Only the verification document
uses schema version 2.

## Intentional non-goals

v0.2.0 does not provide:

- Agent process control;
- hooks or tool interception;
- an Agent Team or Expert Pool;
- an automatic verifier;
- a Ledger or Trust score;
- CI pull-request authority;
- signatures or remote attestation;
- a preventive sandbox; or
- data loss prevention (DLP).

## Known limitations

- Source Binding is a local bounded observation.
- Harness does not defend against a same-user rewrite of the complete Evidence
  set and its manifest.
- Bundle and completion validate a saved Run; they do not rerun its checks.
- Harness does not lock the filesystem after S2 is collected or after
  `complete` returns.
- `complete` is not a secret-redaction step. Check logs and other Evidence may
  contain sensitive values.
- Recording a Manual Verdict does not establish that the reviewer was actually
  independent.
- Local Evidence is not an immutable central audit store.
- v0.2.0 does not claim support for every special Git state.

## Installation and artifacts

Install the release tag:

```bash
python3 -m pip install \
  "git+https://github.com/jgoneit/seal-legacy.git@v0.2.0"
```

The Python distribution remains `outcome-harness`. The CLI and Codex Plugin
remain `harness`.

Release artifacts:

- `outcome_harness-0.2.0-py3-none-any.whl`
- `outcome_harness-0.2.0.tar.gz`

## Release verification

The `v0.2.0` tag workflow runs contract synchronization, the full unittest
suite, wheel and source-distribution builds, `twine check`, clean-wheel CLI and
public-import smoke tests, packaged-resource checks, and an installed lifecycle
smoke before creating a GitHub Release.
