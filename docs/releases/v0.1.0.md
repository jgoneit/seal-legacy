# Outcome Harness v0.1.0

Language: English | [한국어](v0.1.0.ko.md)

## Highlights

Outcome Harness v0.1.0 is the first Experimental release to support evidence-based completion by preserving Task changes and verification results as reviewable Evidence Runs without controlling how an Agent works.

## Included

- Task snapshots and Git baseline recording
- Scope-based change collection, argv-based check execution, and mechanical Evidence storage
- Canonical Verdict validation, Run integrity validation, and a Run Evidence Manifest
- Raw-byte digests and the `evidence_sha256` local consistency identifier
- Portable verifier bundles, manual Verdict record/show, and fail-closed completion
- Stable exit codes, a wheel package, and GitHub Actions CI

## Known Limitations

- Current-source binding is not supported. If source changes after verification, `complete` still reads only the stored Run Evidence.
- `verify --base-ref` can override the Task baseline for an individual Run.
- A digest provides only a local consistency check; it does not provide a remote trust anchor, signature, attestation, or immutable storage.
- This version is Experimental and does not claim to be tamper-proof or ready for production or enterprise enforcement.
- Multimodal Evidence and an external verifier adapter are not included.

## Installation

After the Git tag has been published, install with:

```bash
python3 -m pip install \
  "git+https://github.com/jgoneit/harness.git@v0.1.0"
```

Use a GitHub Release wheel asset only after the Release has actually been created. This document does not hard-code an asset URL in advance.

## Verification

On a `v0.1.0` tag push, the release workflow runs contract synchronization, the full unittest suite, wheel and sdist builds, `twine check`, and a clean-wheel CLI and resource smoke test. It creates the GitHub Release and wheel/sdist assets only after those checks pass.
