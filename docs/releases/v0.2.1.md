# Harness v0.2.1

Harness v0.2.1 is an Experimental patch release of the local
outcome-verification Core and Codex Plugin. It publishes the managed Plugin
workflow introduced after v0.2.0 while preserving the v0.2 Core CLI, Evidence,
Verdict, Bundle, completion, and source-binding contracts.

## Highlights

- **Managed `$harness` workflow:** an explicit work request produces a Task
  draft and one confirmation covering Task creation, ordinary implementation,
  and the first verification exactly once.
- **Evidence identity handoff:** after successful Evidence recording, the
  Plugin reports the exact Task ID, Run ID, and Evidence path, then stops until
  the user explicitly requests a later operation.
- **Repository-bound identities:** conversation-carried Task and Run IDs remain
  bound to the original canonical repository root and are not resolved in a
  different checkout.
- **Explicit escape hatches:** `$harness:task`, `$harness:verify`,
  `$harness:bundle`, and `$harness:complete` remain available for focused
  operations and recovery.
- **Safe bundle default:** when a bundle request omits its output path, the
  Plugin selects a fresh absolute directory outside the target repository and
  passes it through Core's required `--output` argument.

## Authority boundaries

- Core remains the only authority for Task normalization, stored Run
  integrity, Verdict validation, source binding, and completion policy.
- The Plugin does not read raw `verification.json` to decide the next
  lifecycle step. Core v0.2.x successful `verify` stdout establishes only that
  Evidence was recorded and returns its identity.
- Bundle success establishes an integrity-valid export. It does not establish
  a mechanical pass, create an independent Verdict, collect S2, or prove
  completion eligibility.
- Completion still requires a separate final confirmation and an explicit
  `harness complete` operation.
- Failed Core operations stop without automatic repair, replacement Evidence,
  a replacement Run, or retry.

## Core compatibility

- The public CLI commands, stdout JSON fields, stderr behavior, and stable exit
  codes are unchanged from v0.2.0.
- Verification Evidence remains source-bound schema version 2 only.
- Task, changed-files, checks, Run Manifest, Bundle, Verdict, Completion, and
  Source Snapshot schema versions are unchanged.
- `validate_run()` remains the sole public authority for stored Run integrity.
- Core and Plugin Skills support Core `>=0.2.0,<0.3.0`.
- v0.1.x verification Runs still require the corresponding v0.1.x CLI; there
  is no in-place Evidence migration.

## Known limitations

- Source Binding is a local bounded observation and does not lock the
  filesystem after S2 collection or completion.
- Harness does not select or execute an independent reviewer.
- Recording a Manual Verdict binds it to a Task and Run but does not prove
  reviewer independence.
- Local Evidence is not an immutable central audit store.
- Check logs and exported bundles may contain sensitive values and require
  inspection before sharing.

## Installation and artifacts

Install the release tag:

```bash
python3 -m pip install \
  "git+https://github.com/jgoneit/harness.git@v0.2.1"
```

Release artifacts:

- `outcome_harness-0.2.1-py3-none-any.whl`
- `outcome_harness-0.2.1.tar.gz`

The Python distribution remains `outcome-harness`. The CLI and Codex Plugin
remain `harness`. Installing the Python package does not install the Codex
Plugin; refresh the Plugin separately through its configured marketplace.

## Release verification

The `v0.2.1` tag workflow runs the contract synchronization check, the full unittest
suite, wheel and source-distribution builds, `twine check`, clean-wheel CLI and
public-import smoke tests, packaged-resource checks, and the installed CLI
lifecycle smoke before creating a GitHub Release.
